# 架构说明

## 目标分层

CryptoStaticLib 采用简单三层结构：

1. **公共接口层**：`include/crypto_static_lib/`，只暴露稳定的公共声明。
2. **实现层**：`src/`，包含实现细节，不对外暴露内部头文件。
3. **验证层**：`tests/`，覆盖单元测试与最小消费者夹具。

## 目录边界

- `include/` 之外的实现细节不得被公共头文件引用。
- `src/` 不得包含 `tests/` 的任何内容。
- `tests/consumer/` 是独立 CMake 工程，只通过安装后的包接口消费，禁止直接引用源码树头文件。
- 生成文件（如 `version.h`）位于构建目录的 `generated/` 下，不参与源码提交。

## 命名空间

- 所有公共符号位于 `crypto_static_lib` 命名空间。
- 内部符号放在匿名命名空间或 `detail` 子命名空间中。

## C++20 与 ABI

- 统一使用 C++20，关闭编译器扩展（`CXX_EXTENSIONS OFF`）。
- 公共头文件只使用标准库与稳定类型。
- 当前静态库不承诺跨编译器/跨运行时的二进制兼容；同一构建工具链内使用。

## 静态链接的多副本风险

静态库被多个模块分别链接时，会各自持有内部状态副本。涉及全局状态、密钥缓存或单例时，必须明确多副本语义，避免假设"全进程只有一份"。当前版本无全局可变状态，`version()` 返回只读常量引用。

## 依赖策略

- 不引入第三方运行时依赖。
- 新增依赖必须经过评审，说明来源、许可证、可审计性与构建影响。

## 未来密码算法要求

后续实现密码算法时：

- 必须使用经过验证的基元与成熟实现思路，禁止自创密码学。
- 每个算法必须附带官方或公认测试向量。
- 必须评估常量时间特性与内存安全。
